# DeepSeek 安全視角補充範本(對應 CC 的 `security-review`)

> 用途:第10步矩陣判定這次改動碰到認證/輸入解析/外部資料/密鑰/網路請求,需要加一層安全視角。
>
> **不是獨立任務**——直接把下面這段檢查清單併進 `brief-chained-review.md` 的「這次要聚焦的重點」欄位一起送出,同一次複審跑完,不要為了安全視角另外再開一趟 dsh session。

---

## 安全檢查清單(併入複審任務書的重點欄位)

除了一般的正確性審查,額外檢查下面幾點,發現一樣寫進同一份 `FINDINGS.md`:

- **密鑰/憑證外洩**:code 裡有沒有硬編碼的 API key、密碼、token;log/報錯訊息裡會不會不小心印出敏感值。
- **注入類**:SQL 拼字串組查詢、shell 指令組字串執行、模板渲染沒跳脫使用者輸入(XSS)。
- **權限/驗證**:有沒有該檢查身份卻沒檢查的操作;有沒有該檢查資源歸屬(authz)卻只檢查登入與否(authn)的地方。
- **邊界輸入驗證**:外部輸入(使用者輸入、第三方 API 回應、檔案內容)進系統前有沒有做基本驗證,還是直接信任拿來用。
- **依賴/供應鏈**:這次改動有沒有新增依賴,版本是不是明顯過舊或來源可疑。

## 驗收條件(疊加在複審任務書原本的驗收條件上)

- [ ] 上面五類至少都掃過一遍,`FINDINGS.md` 裡對安全類發現額外標注 `[SECURITY]` 前綴方便 CC 抽查時快速定位
- [ ] 沒發現安全問題一樣要老實寫,不要為了交差硬湊
